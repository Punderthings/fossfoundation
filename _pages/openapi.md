All of our data is published as static, read-only files: there is no server to query, so anything you can download, you can cache and cite.  There are two API versions.  **v1** is the original, historical API, which reads foundation records from raw GitHub.  **v2** is the new API, published on this website under `/api/v2/`, which datasets are moving to one at a time.  The naming rules for v2 are recorded in the [URL naming plan](https://github.com/Punderthings/fossfoundation/blob/main/_prompts/2026-11-01-url-standards-for-datasets.md).

## v1: foundation records from raw GitHub

v1 is described by [`openapi/v1/openapi.yaml`](https://github.com/Punderthings/fossfoundation/blob/main/openapi/v1/openapi.yaml) (OpenAPI 3.0), with [interactive documentation](/openapi/).  Its server is `https://raw.githubusercontent.com/Punderthings/fossfoundation/main/`, so it serves the source files in this repository.  It stays available for compatibility, and its URLs will not change.

It has two operations, both for foundations:

- **List foundations** (`getFoundations`): `GET /_foundations/list.json` returns every foundation identifier, with its domain and common names so tools can look one up by name: `{"almalinux": ["almalinux.org", "AlmaLinux", "AlmaLinux OS Foundation"], "asf": ["apache.org", ...`.  The file is generated by [`openapi_builder`](https://github.com/Punderthings/fossfoundation/blob/main/assets/ruby/openapi_builder.rb).
- **Get one foundation** (`getFoundationById`): `GET /_foundations/asf.md` returns that foundation's record as YAML front matter, whose fields match [`openapi/v1/foundation-schema.yaml`](https://github.com/Punderthings/fossfoundation/blob/main/openapi/v1/foundation-schema.yaml):

```YAML
---
identifier: asf
commonName: Apache Software Foundation
legalName: Apache Software Foundation
website: https://www.apache.org/
foundingDate: '1999'
etc.
```

Other source files, such as `_data/sponsorships/*.json` and `_data/p990/<ein>.json`, can be read from raw GitHub the same way, but v1 doesn't describe them.

## v2: datasets on this website

v2 files are served from `https://fossfoundation.info/api/v2/`, one folder per dataset, with one file per record named by its identifier: `/api/v2/{dataset}/{id}.json`.  New datasets use standard vocabularies such as Schema.org and JSON-LD, and are licensed [CC0-1.0](https://creativecommons.org/publicdomain/zero/1.0/).

Available now:

- **[Platform crosswalk](crosswalk#exports)** in [`/api/v2/crosswalk/`](https://github.com/Punderthings/fossfoundation/tree/main/api/v2/crosswalk): one JSON-LD file per foundation, such as `/api/v2/crosswalk/asf.json`, with computed confidence for each account and package; a JSON-LD `context.jsonld` and `vocab.jsonld`; and `stewards.jsonl`, one line per link, for bulk joins with ecosyste.ms.  It moved here from `/api/v1/crosswalk/`, which has been removed.

There is no OpenAPI description of v2 yet; it is planned as `/api/v2/openapi.yaml`.

## Roadmap

These are the next steps of the [URL naming plan](https://github.com/Punderthings/fossfoundation/blob/main/_prompts/2026-11-01-url-standards-for-datasets.md), each in its own pull request:

- **Shared files:** a [DCAT](https://www.w3.org/TR/vocab-dcat-3/) catalog of every dataset at `/api/v2/catalog.jsonld`, one JSON-LD context and vocabulary for all datasets, published copies of our schemas under `/api/v2/schemas/`, and the v2 OpenAPI description.
- **Existing datasets moving to v2:** [foundations](fdnmodel) (`/api/v2/foundations/`, with `_foundations/` and `list.json` unchanged), [sponsors](sponsors), [sponsorships](sponsorships), [entities](entities), sponsor lists and their history, [hosted projects](projects), and [ProPublica 990 tax data](taxes#propublica-990) (`/api/v2/propublica-990/`).
- **New datasets, starting in v2:** [IRS 990 tax data](taxes#irs-990) (`/api/v2/irs-990/`), parsed from the IRS's own e-file XML; [budgets](budgets) from organizations' own reports; foundation leadership; and non-US tax data, named for each source.
- **Later:** citation metadata for datasets, and a glossary of key terms.

See also the [list of datasets](data) and our [roadmap and help wanted](roadmap).
